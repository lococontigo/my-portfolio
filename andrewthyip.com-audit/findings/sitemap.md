## Bilingual URL Structure / hreflang — Correcting the Brief's Assumption

The audit brief stated the site "does NOT use sitemap-level hreflang annotations as far as is known" and asked to verify. **This is not accurate for the current live sitemap** — it was true at some earlier point but has since been fixed:

- Every `<url>` block includes three `<xhtml:link rel="alternate">` entries: `hreflang="en"`, `hreflang="zh-Hant"`, and `hreflang="x-default"`.
- The annotations are **reciprocal** — the EN and ZH versions of a given page both list the same three alternates, which is what Google's hreflang validation requires (a common source of hreflang errors is one-directional annotation).
- `x-default` consistently points to the English URL across all 12 pairs, correctly reflecting `defaultLocale: 'en'` in `astro.config.mjs` (`i18n.routing.prefixDefaultLocale: false`).
- Cross-checked against the live page `<head>`: `https://andrewthyip.com/` includes matching `<link rel="alternate" hreflang="...">` tags identical to the sitemap's, plus a correct `<link rel="canonical" href="https://andrewthyip.com/">`. Sitemap and on-page annotations agree — no conflicting signals.

**Conclusion:** this is a strength, not a gap. No action needed. (Recommend correcting whatever earlier documentation/brief claimed hreflang was missing, so this doesn't get "fixed" again by mistake.)

## Quality Gate Warnings

Not triggered. Zero location pages exist on this site; the 30+/50+ location-page thresholds are not applicable.

## Recommendations

1. **No urgent fixes required** — sitemap is valid, complete, accurate, and has no dead/orphaned/redirected URLs.
2. (Low priority, process) Consider generating `lastmod` values from an automated source (e.g. a small Astro/Node build step that reads `git log -1 --format=%ad -- <file>` per page, or switching to the `@astrojs/sitemap` integration with per-page `lastmod` wiring) instead of hand-editing `public/sitemap.xml`. Today's values are plausible, but manual maintenance is the most likely place for this sitemap to silently drift out of sync as pages change.
3. Keep the current hreflang setup as the template for any future locales — the reciprocal `xhtml:link` pattern plus matching on-page tags is correct and should not be altered.
